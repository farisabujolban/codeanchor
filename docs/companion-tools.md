# Companion tools and rule migration

Use CodeAnchor for checks that compare files or revisions: staged code versus its leading comment, README commands versus package scripts, CI runtime versions versus repository pins, and frequently changed files versus tests and owners. Run the tools below as separate checks through your usual task runner or CI. CodeAnchor does not install or run them.

Some checks answer related questions. A frozen install verifies that the lockfile resolves the manifest; `CA-LOCK001` asks whether a dependency change and its lockfile update are in the same diff. Redocly validates the OpenAPI document; `CA-OPENAPI001` compares routes in that document with routes found in supported JS/TS frameworks.

## Replace retired rules

Enable the replacement before upgrading if the old rule was a required check. Remove retired IDs from `codeanchor.config.json` and any `--rules` arguments. Old config entries have no effect, and an explicit `--rules` list containing a retired ID is rejected.

| Retired rule    | Replacement and setup                                                                                                                                                                                                                                                                                                         |
| --------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `CA-CI004`      | [zizmor: `unpinned-uses`](https://docs.zizmor.sh/audits/#unpinned-uses). Require hash pinning for the actions your policy covers.                                                                                                                                                                                             |
| `CA-CI006`      | [zizmor: `excessive-permissions`](https://docs.zizmor.sh/audits/#excessive-permissions). It audits permissions at both workflow and job level.                                                                                                                                                                                |
| `CA-CI007`      | [zizmor: `ref-version-mismatch`](https://docs.zizmor.sh/audits/#ref-version-mismatch). Use `--persona pedantic` to report missing version comments as well as mismatches.                                                                                                                                                     |
| `CA-DOCKER004`  | [Docker BuildKit: `SecretsUsedInArgOrEnv`](https://docs.docker.com/reference/build-checks/secrets-used-in-arg-or-env/). Run `docker build --check` against each build target and set the build checks to fail on violations if this is a gate. It can flag sensitive keys even without defaults.                              |
| `CA-COMPOSE001` | [Docker Compose](https://docs.docker.com/reference/cli/docker/compose/config/). Run `docker compose config --quiet` with the same files and profiles you use to start the project. Compose validates the merged model, including service dependencies and named networks and volumes.                                         |
| `CA-DOCS002`    | [Lychee](https://github.com/lycheeverse/lychee#usage). Run `lychee --offline '**/*.md'` for local links. Omit `--offline` in a separate check if you also want to check external URLs.                                                                                                                                        |
| `CA-OPENAPI002` | [Redocly CLI: `no-unresolved-refs`](https://redocly.com/docs/cli/rules/oas/no-unresolved-refs). Enable the rule as an error and lint each OpenAPI entry point.                                                                                                                                                                |
| `ISO-MAI001`    | [dependency-cruiser](https://github.com/sverweij/dependency-cruiser/blob/main/doc/rules-reference.md) with a circular dependency rule for JS/TS; [Pylint: `cyclic-import`](https://pylint.readthedocs.io/en/latest/user_guide/messages/refactor/cyclic-import.html) for Python. Configure import resolution for your project. |

## Optional companion checks

| Need                                      | Tool                                                                                                                                                                                                                                                                          |
| ----------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Type checking and language linting        | Use [TypeScript](https://www.typescriptlang.org/tsconfig/), [typescript-eslint with type information](https://typescript-eslint.io/getting-started/typed-linting/), or [Ruff](https://docs.astral.sh/ruff/) and [mypy](https://mypy.readthedocs.io/en/stable/) for Python.    |
| Unused code and dependencies              | Use [Knip](https://knip.dev/overview/getting-started) for JS/TS files, exports, and dependencies, and [deptry](https://deptry.com/) for Python dependency declarations.                                                                                                       |
| Secret scanning and dependency advisories | Use [Gitleaks](https://github.com/gitleaks/gitleaks) for staged changes and history. Run your package manager's advisory scanner against locked dependencies, such as [pnpm audit](https://pnpm.io/cli/audit) or [pip-audit](https://github.com/pypa/pip-audit).              |
| Source security analysis                  | Use [Semgrep](https://semgrep.dev/docs/) with rules selected for the languages and frameworks you ship.                                                                                                                                                                       |
| Package and image checks                  | Run [publint](https://publint.dev/) after building an npm package to check what consumers receive. Use [Hadolint](https://github.com/hadolint/hadolint) for Dockerfile linting and [Trivy](https://trivy.dev/) for image scanning.                                            |
| Tests and coverage                        | Run your test suite and collect coverage with tools such as [Vitest](https://vitest.dev/guide/coverage) or [Coverage.py](https://coverage.readthedocs.io/). CodeAnchor's history checks report missing or untouched test files; they cannot tell whether behavior was tested. |

For JavaScript and TypeScript comment and environment policies, see the [companion ESLint plugin](https://github.com/farisabujolban/eslint-plugin-codeanchor).
